AI Critique
The AI performed well in generating the overall structure of the automation tests, including data-driven test cases, Playwright scripts, selectors, API-based test-data setup, and reusable testing patterns. However, it was not completely reliable when decisions required detailed inspection of the actual application behavior. One concrete issue was the use of page.getByText('Dashboard') with toBeVisible(). The Dashboard text appeared in both the sidebar and the main <h2> heading, causing Playwright strict-mode failure because the locator resolved to multiple elements. The AI failed to anticipate this ambiguity because it treated visible text as a unique identifier rather than checking how the same text was represented across the DOM. The AI also initially relied on assumptions about currency formatting instead of fully accounting for locale-dependent thousands separators. These issues demonstrate that AI can generate syntactically valid and logically plausible tests while still missing implementation-specific details. The main principle I learned is that AI should be treated as a test-generation assistant, not an autonomous tester. Human review is necessary to verify selectors against the actual DOM, confirm API behavior, inspect seed data, and execute the generated tests. The most reliable workflow is AI generation → source-code verification → test execution → human review → correction → final execution.
